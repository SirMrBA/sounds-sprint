# Sounds Sprint

An English-language study companion for **English Sounds and Sound Systems (SoSe 2026)**, prepared for the **16 October 2026 resit, 10:00–12:00, HGA 30**.

- Site: https://sirmrba.github.io/sounds-sprint/
- Public source repository: https://github.com/SirMrBA/sounds-sprint
- The GitHub Pages website itself is public. Original course PDFs and Moodle credentials are not included.

## Study tools

- 10 lessons with 57 concise explanations and examples
- 93 flashcards with Again / Got it ratings and a due queue
- 119 questions with answer explanations and a persistent mistake list
- An interactive 24-consonant / 12-vowel IPA studio
- All 176 entries from the challenging-word keys, including the two repeated entries
- RP / GA word transcription with an IPA keyboard and supported alternative notation
- 6 sentence/passage exercises with independent RP / GA drafts and self-review
- The supplied official mock: 11 theory groups, 31 answer fields, and a transcription passage
- 18 automatically checked theory fields and 13 explicitly self-reviewed open fields; no invented official point weighting or pass mark
- Optional practice timer; exam answers survive reloads
- Printable HTML and 2-page A4 PDF cheat sheet
- Browser-local progress, export/import, offline caching and a web app manifest

There is no server, analytics or account system. Progress is stored in localStorage on the current origin and device. Browser storage can be cleared by the user or browser. Export/import is explicit; there is no cloud sync.

## Run locally

Serve this directory with any static HTTP server, for example:

```sh
python3 -m http.server 8773 --bind 127.0.0.1
```

Then visit `http://127.0.0.1:8773/`. No build or package installation is required. `data.js` is generated by `build-content.py` from its authored lessons and the extracted `words.json`. Running the generator overwrites `data.js`.

## Sources and editorial choices

The supplied course outline, lecture slides, seven word-key lists, three parts of the official mock, wrap-up solutions and transcription keys are the primary content sources. Each lesson and exercise displays a source reference. Source files are retained in the local Obsidian vault, not in this repository.

- The three mock PDFs are parts of **one exam**, not three exams.
- The course requires both theory and transcription to be passed separately.
- Source filenames sometimes lag the slide title's session number. References use the content title.
- Optional raised schwa is displayed as `(ə)`. Some italic optional-segment formatting is unavailable in plain-text extraction. Word mismatches require comparison and self-assessment rather than being automatically counted wrong.
- The likely RP `tournament` typo `/tʊe…/` is corrected to `/tʊə…/` against [Cambridge Dictionary](https://dictionary.cambridge.org/pronunciation/english/tournament), which also supports `/ˈtɔːnəmənt/`.
- Course-specific notation is retained and labelled; it is not a claim about every real-world RP or GA speaker.
- The simplified early syllable definition is qualified by the later syllabic-consonant lesson. Aspiration includes the /s/-cluster exception.
- Sentence stress and connected-speech patterns can vary. Passage solutions are models with feature-based self-review, not automatic grades.
- Dictionary audio and the [official IPA Association chart](https://www.internationalphoneticassociation.org/content/ipa-chart) open as external resources and need internet.

## Files

`index.html`, `styles.css`, `app.js`: app and interactions. `data.js`: lessons, cards, questions, words, passages. `mock.js`: official mock adaptation. `cheat-sheet.html`: standalone printable guide (works without JavaScript). `Sounds-Sprint-Cheat-Sheet.pdf`: printable export. `sw.js`: offline cache. Icons and manifest: home-screen installation.

## Maintenance

When changing static assets, update the cache name in `sw.js`. A deployed asset update is fetched from the network when online; the version change keeps offline caches consistent. Re-export and visually review the cheat-sheet PDF after changing its HTML. Do not upload original PDFs, access codes, or personal registration information.

See `QA.md` for verification and its limits.
